# 2026-08-11 ライセンスを MIT とし、コントリビューションを inbound = outbound で受け入れる

- 課題: リポジトリはすでにpublicだが `LICENSE` がなく、法的には既定（All rights reserved）のままだった。README がコントリビューション手順を案内している一方で、外部コントリビューターは自分の貢献がどう扱われるかを判断できない状態だった。README 自身も「本番公開前にプライバシー方針とライセンスを確定してください」と公開前の条件に挙げていた（Issue #3）。
- 決定: コードのライセンスを **MIT License** とする。著作権者の表記は `henkaku Community` とし、`Copyright (c) 2026 henkaku Community` を `LICENSE` に記載する。
- 適用範囲: リポジトリのコード・ドキュメント・素材（画像・音源など）に適用する。第三者から取り込んだ素材が別の条件で提供されている場合は、その素材の配置場所に明記する。
- コントリビューションの扱い: Pull Request はリポジトリと同じ MIT License で提供されたものとみなす（inbound = outbound）。CLA の署名や著作権の譲渡は求めない。参加時の負担を増やさないためで、MIT・Apache-2.0 のどちらでも一般的な慣行にあたる。`henkaku Community` は代表表記であり、権利を集約するものではない。
- MIT を選んだ理由: henkaku-center の public リポジトリ36件のうち `LICENSE` があるのは7件で、いずれも MIT だった（`henkaku-community` / `henkaku-wiki` / `kamon-nft` / `henkaku-nengajo-contract` / `henkaku-ticket-contract` / `henkaku-ticket-contract-old` / `henkaku_ipfs_uploader`）。organization の慣行に揃う。
- 採らなかった案: Apache-2.0。特許の明示的許諾とコントリビューターからの特許許諾（第3条）が利点だが、このリポジトリは Next.js アプリと Supabase スキーマで独自のアルゴリズムを含まず、具体的な特許リスクの想定がない。条文の短さと org 内の前例で MIT を採った。
- 採らなかった案: CC0 / Unlicense。著作権表示の保持義務がなくなるため、Issue #13 の「制作者クレジットを残す」という要件と整合しない。
- 画像を別ライセンスにしなかった理由: Issue #3 のコメントで、コード = MIT / イラスト = CC BY 4.0 の2ライセンス構成が提案されていた。「MIT の義務は Software の複製物にライセンス表示を含めることであり、画像をWebページへ埋め込んだ第三者が何をすれば条件を満たすのか文面から読み取れない」という指摘は妥当で、CC BY なら帰属表示がライセンス上の義務になる。それでも全体を MIT に揃えたのは、適用範囲がリポジトリ単位で単純になることを優先したため。**クレジットはライセンス上の義務ではなく運用ルールとして守る。**
- 素材を追加するときの手順: 収録前に、提供者から MIT License での利用・改変・再配布について許諾を得る。クレジット掲載の希望と名義・掲載場所を確認し、許諾を得たことと希望された表記を後から確認できる形で記録する。手順は `CONTRIBUTING.md` に書いた。
- 音源について（今回は決めていない）: 音楽の追加が想定されているため、適用範囲の文言を「画像」から「素材（画像・音源など）」へ広げ、`CONTRIBUTING.md` に確認事項を書いた。**音源は画像と同じ手順では足りない。** 作曲・作詞の権利と原盤の権利が別々の人に帰属しうるうえ、JASRAC・NexTone へ信託されている場合は作った本人であっても MIT License で提供できないことがある。実際に音源を収録する段階で、この決定の見直しが必要になる可能性がある。
- 見直しの引き金: 上記の「MIT の義務は Software 向けの文面で、非ソフトウェアの著作物へ適用すると再利用者の条件が読み取りにくい」という指摘は、**画像より音源でいっそう強く効く。** 音源を扱うことが確定した時点で、素材だけ CC BY 4.0 等へ分ける2ライセンス構成を再検討する。
- 影響範囲: `LICENSE` と `CONTRIBUTING.md` を追加し、README のライセンス節と公開前チェックを更新した。公開前の条件として残るのはプライバシー方針（Issue #36）のみになる。
- 残る作業: Issue #13 のイラストは、cinnamonさん本人が MIT での提供に同意しているかの確認が必要（原本は Discord 投稿）。`main` のブランチ保護・必須CI・レビュー要件は GitHub 側の設定で、このリポジトリの変更では行えない。
